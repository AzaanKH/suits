# Broad tailoring catalog

Three.js with React Three Fiber remains the rendering stack. Fiber is a React renderer for Three.js, which fits the existing Next.js application and its shared configuration state. The app uses on-demand rendering and prepared GLB assets. Babylon.js also supports the required rendering features; no demonstrated requirement justifies replacing the current stack. [React Three Fiber](https://r3f.docs.pmnd.rs/getting-started/introduction), [performance guidance](https://r3f.docs.pmnd.rs/advanced/scaling-performance), [Babylon.js capabilities](https://www.babylonjs.com/specifications/)

The editor now has a Details step with 62 additional choice fields and 18 optional finished-garment dimensions. The existing fabric, jacket style, lapel, button, pocket, trouser, and extras selectors remain the reference design. Details records additional requests against that reference. This is a broad catalog of tailoring possibilities, not a statement that every combination has been approved for production.

| Area             | Covered requests                                                                                                                                                                                                                            |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Cloth and facing | Separate trouser and waistcoat cloth, lapel facing, lining color and material, undercollar, pattern matching                                                                                                                                |
| Jacket           | Additional front cuts, silhouette, canvas, shoulders, sleeve head, lapel width/gorge/roll, button stance, front quarters, vents, breast/ticket/interior pockets, lining coverage, sleeve lining, cuff buttons and buttonholes, sleeve shape |
| Trousers         | Independent waist treatment, pleats, pleat direction, brace buttons, rise, waistband construction, closure, fly, pockets, leg cut, hem, break, crease, lining, heel guard                                                                   |
| Waistcoat        | Inclusion independent of the reference jacket, front, neckline, lapels, buttons, pockets, hem, back, adjuster                                                                                                                               |
| Finishing        | Pick stitching, stitch color, buttonhole thread, lapel buttonhole, cuff accent, monogram position/font/thread, trouser braid                                                                                                                |
| Dimensions       | Lapel width; jacket length/chest/waist/shoulders; separate sleeve lengths; trouser waist/seat/rises/thigh/knee/hem/inseam/outseam/turn-up; waistcoat length                                                                                 |

The canonical definitions and validation are in `src/features/customizer/tailoring.ts`. Each field identifies whether it currently changes a material, changes a schematic detail, or is specification-only. Body measurements remain in the existing Fit/profile flow. The new dimensions use centimetres and describe the finished garment. Their numeric bounds reject invalid data; they are not maker-approved sizing limits or fit predictions.

Dependencies are enforced for pleat direction, turn-up depth, waistcoat details, and monogram details. Changing a parent clears dependent requests that no longer apply. No maker has been selected, so the system does not invent universal restrictions for combinations such as a waistcoat with a double-breasted jacket. Existing product-catalog rules still apply to the priced reference design.

The editable `tailoring` field is optional and versioned, so existing saved designs remain readable. Server validation checks field codes, option values, finite positive dimensions, and prerequisites. Saved designs preserve requests on save, load, and duplicate. The review and saved-design pages list them separately from priced selections. The downloaded JSON includes stable IDs, readable labels, the reference design, units, and the unconfirmed maker status.

Any additional request requires a maker quote. The editor labels the current amount as priced selections, and both the cart button and server cart validation prevent treating an unpriced request as included. Manufacturer availability, surcharges, approved combinations, pattern IDs, grading rules, and fit validation remain to be supplied before these requests become orderable production options.

The House Suit now opens in 3D by default. `ENABLE_3D_CONFIGURATOR=false` explicitly disables it. Products without matching assets use the existing 2D preview. Device and runtime fallbacks remain available.

Current 3D coverage includes the original modular assets plus separate trouser/waistcoat colors, lapel facing, lining color, waistcoat inclusion, and independently combinable waist treatment and pleats. These are schematic assets. Most construction, finishing, and dimension requests are recorded without changing geometry, and the interface states that limitation. Real fabric swatches, correctly sewn fronts, vents, cuffs, interior views, realistic drape, and measurement-driven shapes remain asset-production work. The broad catalog does not make the existing generated suit production-ready.

The GLB loader retains ownership of cached geometry. Scene instances borrow that geometry, and each instance receives its own material assignments. Unmounting a detail no longer disposes geometry used by other instances of the same GLB. Material updates explicitly request a new frame.

Validation completed on October 4, 2026: frontend and backend tests include combined trouser choices, dependency cleanup, fabric independence, invalid inputs, stable signatures, saved-design duplication, and server rejection of unquoted cart requests. Browser tests cover desktop and mobile editing, 3D loading, specification downloads, and review. Production garment geometry and physical fit were not validated by these tests.
